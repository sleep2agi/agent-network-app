# Desktop build, acceptance, signing, and release SOP

This is the release gate for the Tauri desktop app on macOS and Windows.

**The signed release path is CI, not a laptop.**
`.github/workflows/release-desktop-auto-update.yml` builds, signs, notarizes,
runs the packaged smoke gates, and creates a **draft** GitHub Release. A human
audits that draft and publishes it. An earlier revision of this document
described signing and notarizing by hand in a logged-in macOS session; that is
no longer the release path and following it produces a build that does not
match what ships.

Two workflows, two purposes:

| Workflow | Produces | Use for |
|---|---|---|
| `.github/workflows/desktop-tauri.yml` | **unsigned** macOS arm64 + Windows x64 bundles, as Actions artifacts | throwaway test builds |
| `.github/workflows/release-desktop-auto-update.yml` | **signed + notarized** bundles, updater signatures, `latest.json`, one **draft** Release | every real release |

Unsigned artifacts are for testing only. Label them as such: macOS Gatekeeper
blocks them and Windows shows SmartScreen.

## 0. Working boundaries on a shared machine

Several agents edit these repositories on the same host. Before anything else:

- Work in a **fresh worktree** created from the exact `origin/main` commit:
  `git worktree add -b <branch> ../anet-app-<purpose> <sha>`. Confirm
  `git status --porcelain` is empty.
- **Never symlink `node_modules` into another checkout.** `npm ci` deletes and
  recreates that directory, so a shared link lets one worktree destroy another
  worktree's dependencies mid-run. Either let npm install inside the worktree
  that owns it, or run the tests in Docker with a **named cache volume of its
  own**.
- **Do not `docker rmi` an image you did not create**, and do not prune shared
  build cache, unless the image is confirmed exclusive to your task *and* you
  have been asked to clean it up.
- Never place a real Hub hostname, token, certificate, or key material in this
  repository, in a PR body, or in a test fixture. Secrets are referenced by
  **name** only.

## 1. Version bump PR

The version is stated in eight files and they must agree:

```
app.json
package.json
package-lock.json           (root "version" and packages[""].version)
src-tauri/Cargo.toml
src-tauri/Cargo.lock        (root package stanza ONLY — see below)
src-tauri/tauri.conf.json
src/version.ts              (APP_VERSION)
src/version-consistency.test.ts (expected)
```

`src/version-consistency.test.ts` is the guard: a partial bump fails
`npm test`. The release tag is generated by the workflow as
`desktop-v__VERSION__`, so a wrong version number is a wrong tag, and a human
cannot correct it at trigger time.

### `src-tauri/Cargo.lock`: change the root package only

Edit exactly this stanza:

```toml
[[package]]
name = "agent-network-desktop"
version = "<new version>"
```

Do **not** search-and-replace the version string across the file. Releasing
v0.2.30 did exactly that (#119) and moved an unrelated crate — `filetime`
happened to sit at `0.2.29` — to `0.2.30` while leaving its checksum line
untouched. `cargo check --locked` then failed on the checksum mismatch, and
#120 had to restore the pinned version. After editing, run
`git diff src-tauri/Cargo.lock` and confirm that **exactly one `[[package]]`
stanza changed**. A second changed stanza is collateral damage; revert it.

Every push and pull request runs `.github/workflows/unit-tests.yml`
(`npm ci && npm test` on ubuntu and windows). Merge only when it is green.

## 2. Trigger the signed release

Take the full 40-character SHA of the merged commit:

```bash
git rev-parse origin/main
gh workflow run release-desktop-auto-update.yml \
  --repo sleep2agi/agent-network-app \
  -f commit=<40-character SHA>
```

The workflow's first step, `Require exact merged commit`, refuses anything
else: the input must match `^[0-9a-f]{40}$`, must equal the checked-out `HEAD`,
and must be an ancestor of `origin/main`. Short SHAs, tags, and branch names
are rejected, and an unmerged commit cannot be released.

The concurrency group is `release-desktop-auto-update` with
`cancel-in-progress: false`. A second trigger queues behind the first; it does
not cancel it. Do not re-trigger because a run looks stalled.

## 3. `macos-signing` environment approval

Both matrix jobs run under `environment: macos-signing` and wait for approval.
Approving authorizes use of the signing material referenced by the workflow:
the Tauri updater key, the Apple Developer ID certificate, and the App Store
Connect API key — all read from repository secrets by name. The Developer ID
identity string is set in the `tauri-action` step; the private key material
never leaves the runner (`$RUNNER_TEMP`, mode 600).

Before approving, confirm the run's input commit is the commit you intend to
release. Approval is what starts consuming signing and notarization quota.

## 4. What CI enforces (all of it must be green)

Matrix: `macos-14 → --bundles app,dmg` and
`windows-latest → --bundles nsis,msi`, with `fail-fast: false` so one platform
failing still reports the other.

1. `npm ci`, `npm test`, `npm run typecheck`, `npx expo export -p web`.
2. Pinned local CommHub sidecar build
   (`npm ci --prefix local-hub-sidecar --ignore-scripts`,
   `npm run build:local-hub-sidecar`).
3. `npx tauri icon assets/icon.png`.
4. `cargo check --locked` — where a bad `Cargo.lock` edit surfaces.
5. `cargo test --locked` for the credential-safety properties:
   `desktop_session_round_trip_uses_native_store`,
   `profile_registry_metadata_never_serializes_secrets`,
   `corrupt_profile_registry_is_quarantined_without_data_loss`,
   `revoked_profile_marker_is_isolated`.
6. `tauri-apps/tauri-action` (pinned by commit SHA, not a floating tag) builds,
   signs, notarizes, and creates the **draft** release
   (`releaseDraft: true`, `prerelease: false`, `updaterJsonPreferNsis: true`).
7. **Packaged smoke gates**, run against the binary inside the built bundle:
   `--smoke-local-hub`, `--smoke-multihub`,
   `--smoke-local-hub-crash-recovery`, `--smoke-local-hub-migration`,
   `--smoke-local-hub-failed-migration`, `--smoke-local-hub-corrupt-data`.
   The migration case is seeded from a **real previous release** of
   `@sleep2agi/commhub-server` via `scripts/seed-previous-local-hub.mjs`, not
   from synthetic data. Each run must leave a non-empty
   `local-hub/data/commhub.db`, and the packaged Hub logs are grepped for
   credential material (`local-hub-bootstrap-password`, `atok_`, `ntok_`,
   `utok_`); any hit fails the job.
8. **Uninstall and reinstall retention.** macOS: install with `ditto`,
   `codesign --verify --deep --strict`, smoke, delete the app, assert
   `commhub.db` and `profiles/index.json` survive, reinstall, smoke again.
   Windows: silent NSIS install, smoke, silent uninstall, assert the binary is
   gone *and* the data survives, reinstall, smoke again.
9. **Size ceiling**: any `.dmg`, `.exe`, or `.msi` over **55 MiB** fails the
   job. At v0.2.30 the `.msi` was 48.7 MB — roughly 6 MB of headroom. Weigh new
   bundled dependencies against that number before adding them.

## 5. Audit the draft before publishing

CI stops at a draft. Publishing is a human action, and it is the last point
with a clean way back.

```bash
gh release view desktop-v<version> --repo sleep2agi/agent-network-app \
  --json tagName,isDraft,isPrerelease,targetCommitish,assets
gh api repos/sleep2agi/agent-network-app/git/ref/tags/desktop-v<version> \
  -q '.object.sha,.object.type'
gh run view <run id> --repo sleep2agi/agent-network-app --json jobs
```

Publish only when all of these hold:

- `targetCommitish` equals the 40-character SHA you triggered with, and the tag
  ref resolves to that same commit;
- both platform jobs concluded `success`;
- the eight expected assets are present: macOS `.dmg` and `.app.tar.gz`,
  Windows `x64-setup.exe` and `x64_en-US.msi`, the `.sig` for each updater
  artifact, and `latest.json`;
- asset sizes match the build log.

An updater signature is bound to the **exact bytes** it signed. Swapping an
asset while keeping its `.sig` breaks updates for every installed client.

## 6. Publish, then sync the manifest

**Order matters and cannot be reversed.** The URLs inside `latest.json` point
at `https://api.github.com/repos/.../releases/assets/<id>`, and assets attached
to a *draft* release are not anonymously downloadable. Publish the release
first; only then deploy the manifest. Deploying first hands every client an
update instruction pointing at an asset it cannot fetch.

Copy the generated `latest.json` from the release into the docs site repository:

```
sleep2agi/agent-network : docs-site/docs/public/desktop/update/latest.json
```

`docs-site/vercel.json` serves that path directly with an explicit
`Cache-Control` header and **no rewrite**;
`docs-site/scripts/check-desktop-update-route.mjs` asserts exactly that, plus a
semver `version` and the presence of the `darwin-aarch64` and `windows-x86_64`
signatures. Run it before deploying. Deploy the docs site to production.

## 7. Verify what users actually get

```bash
curl -sS -D - -L https://www.anet.sh/desktop/update/latest.json -o latest.json
```

Require `200`, `content-type: application/json`, the new `version`, and the
expected platform entries. Then two checks that are easy to skip and are the
ones that catch real breakage:

- **Deployment freshness** — the served file and the file in the docs site
  repository must hash identically. A stale CDN or an undeployed merge shows up
  here and nowhere else.
- **Anonymous reachability** — fetch an asset URL from the manifest with **no
  credentials at all**:

  ```bash
  env -u GITHUB_TOKEN -u GH_TOKEN curl -sS -D - \
    -H 'Accept: application/octet-stream' -L '<asset url from manifest>'
  ```

  Expect `302` to the release asset host, then `200`,
  `content-type: application/octet-stream`, and a `content-length` matching the
  published asset. Testing this with a token proves nothing: users do not have
  one.

## 8. When something fails

**Before `tauri-action` has run** — no tag, no draft, no signed asset exists.
Fix the cause and re-trigger; the same version number may be reused with the
new `main` SHA.

**Once a draft, tag, or any platform asset exists** — the default is to bump
the patch version and release again. Reusing the version is permitted only
when all of the following are true: the failed draft's assets are deleted
precisely by asset ID, the tag is re-bound to the exact intended target, the
run is repeated in full, and a maintainer has explicitly authorized the reuse.
Otherwise a single tag ends up holding artifacts built from two different
commits.

**Once published** — a release cannot be recalled; clients may already have
updated. The only remedies are to point `latest.json` back at the previous
version (which stops further upgrades but does not downgrade anyone) or to ship
a higher version. This is why the audit in section 5 is the real gate.

Never, under any circumstance:

- overwrite or replace an asset of a published release, including re-uploading
  a file with the same name;
- move or recreate a published tag;
- publish a draft that failed any gate in section 4;
- copy signing key material, certificate contents, or the App Store Connect key
  anywhere outside the runner — not into a log, a message, an attachment, or a
  file in this repository.

Nothing in this document requires touching a production service. If a step
seems to, stop: that is a sign the wrong path is being followed.

## 9. Release notes are user-facing

`releaseBody` in the workflow becomes the GitHub release body **and** the
`notes` field of `latest.json`, which the in-app updater shows to users.
v0.2.30 shipped `"Publish this draft only after installation smoke tests
pass."` — an instruction to ourselves, displayed to everyone who saw the update
prompt. Keep release discipline in this document; keep the notes about what the
user is getting. `src/release-notes-hygiene.test.ts` enforces the boundary.

## Appendix A: Tauri constraints that still apply

These are properties of the app, independent of how it is signed.

**Never replace `globalThis.fetch` with `@tauri-apps/plugin-http.fetch`.**
Tauri's macOS IPC uses the global fetch implementation; replacing it creates
recursive `plugin fetch -> invoke -> IPC fetch` calls and eventually an
unresponsive WebProcess. Call the plugin explicitly through `appFetch`.

**HTTP capability scopes must cover explicit ports.** Alongside the
default-port patterns, both of these are required:

```json
{ "url": "http://*:*/*" }
{ "url": "https://*:*/*" }
```

Without them a Hub on a non-default port is rejected before the request leaves
the app, which looks like a generic network failure.

## Appendix B: Manual acceptance of an unsigned build

Useful when validating UI behaviour from a `desktop-tauri.yml` artifact. Run
the app against a real Hub on a non-default port and verify:

1. Login reaches the Agents screen with the authenticated profile visible.
2. The app stays responsive for at least 15 seconds, with no
   `WebProcessProxy::didBecomeUnresponsive` in the system log.
3. `Cmd+V` pastes an image attachment and the send button clears the preview
   after submission.
4. Copying a non-image file in Finder and pasting it produces a file preview
   that sends successfully.
5. Plain text paste still enters the composer and is not converted into an
   attachment.
6. Every uploaded file downloads from its file API URL with the expected
   status, MIME type, size, and bytes.

Locate controls from the current window bounds or accessibility data. Absolute
click coordinates borrowed from another window position produce misleading
results — a click landing at the edge of a text field looks like a broken send
button.
