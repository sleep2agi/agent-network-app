desktop v0.2.82 — 托盘下拉改成飞书式面板(头像 + 未读数 + 忽略全部)
================================================================================

来源：Vincent 2026-09-20 task a79aec46「通知用这个啊」(截图：飞书菜单栏通知面板)

参照物：应用名在左上、「忽略全部」在右上、每行 = 圆头像 + 名字 + 右侧红色未读数。

现状(0.2.76)：托盘下拉是**原生菜单**，一行只能是纯文本「N  <alias>」——
              画不出头像，也画不出红色角标。所以这一版换成自绘窗口。

A. 面板本体
--------------------------------------------------------------------------------
新窗口 `tray-panel`：无边框、置顶、不进任务栏、失焦即收起、Esc 关闭，URL `?tray=1`。
内容：应用名 / 「忽略全部」 / 每行 AliasAvatar(32) + 别名 + 红色未读数 / 空状态文案。
行按未读数降序（顺序由 trayModelFrom 定，面板不再排一次）；超过一屏可滚。

🔴 面板是**独立 webview**，读不到主窗口的 unread-store。
   链路：主窗口 → `tray_update`(Rust 存一份) → 面板 `tray_panel_model` 取
        + 订阅 `tray-model` 实时更新。
   ⇒「数只有一个来源」这条没破：仍然是 unread-store，Rust 只转了一手。
   ⇒ 面板**不碰 hub、不拿 token**（契约测试钉住 `HubConfig`/`serverUrl` 不出现）。

动作也不在面板里落地：
  · 点行   → `tray_open_chat` → 复用 0.2.76 那条 `tray-open-chat` 事件（前端监听没变）
  · 忽略全部 → `tray_dismiss_all` → 主窗口用会话里同一条 agent 级 ack 清
             （老 hub 不认 `{agent}` 时同样退回按 id）

「忽略全部」的目标 = **面板当时列出来的那些**，不去读全量：
托盘本来就截断到 20 行，读全量等于清掉用户根本没看见的会话 ——
那是「按钮做的事比它说的多」，比少清更糟。

B. 🔴 Linux 做不到，所以 Linux 不做
--------------------------------------------------------------------------------
tauri 2.11.5 `src/tray/mod.rs:66` 逐字：
    "Linux: Unsupported. The event is not emitted even though the icon is shown"
同文件另一条：菜单一旦设上就不能移除或替换。
⇒ Linux 上既收不到点击事件、也换不掉菜单，自绘面板在那里做不出来。

处置：`show_menu_on_left_click(cfg!(target_os = "linux"))`
  · Linux      ：继续用原生菜单（行为与 0.2.76 完全一致）
  · macOS/Win  ：左键出面板；**右键仍出原生菜单** ⇒「打开 Agent Network / 退出」
                 还在原处可达（这是菜单被左键让出去之后它们的去处）

托盘图标与未读数标题：与 0.2.79 完全一致，本版未动。

C. 位置
--------------------------------------------------------------------------------
`panel_position()` 纯函数（物理像素）：
  · 横向：以托盘图标为中心
  · 纵向：图标在屏幕上半 → 面板放下方（macOS 菜单栏在顶）
          图标在屏幕下半 → 面板放上方（Windows 任务栏通常在底）
  · 最后夹回当前显示器工作区；工作区比面板还小时贴左上，不算出负坐标
数据来自 `TrayIconEvent::Click { rect, .. }`（tray-icon 0.24.2 提供图标矩形）。

🔴 面板代码在 Linux 上被 cfg 排除、**根本编不到**，所以特地临时放开 cfg 编了一次。
   当场抓出两个只会在 macOS/Windows CI 才暴露的编译错：
     · `log::warn!` —— `log` 不是本 crate 的依赖（改用 eprintln!，与 lib.rs 一致）
     · `tauri::tray::Rect` 是**私有**的 —— 公开路径是 `tauri::Rect`
   改完再把 cfg 收回去。若没做这一步，这两个错会在发版工作流里才炸。

两向见证（每条都先红后绿）：

  · 忽略全部只清第一个      → 两条目标集合断言红
  · 撤掉 capability 里的 `tray-panel` → 契约红（新窗口会一个 core 权限都没有）
  · 去掉 AliasAvatar        → 契约红

E. 平台验证边界（本机是 Linux，说清楚哪些没验）
--------------------------------------------------------------------------------
已验：面板内容与两种主题的渲染（web 导出 + Playwright）、位置计算（Rust 单测）、
      整包编译（Linux 目标）、Linux 仍走原生菜单这一分支。
未验：**真实 macOS 菜单栏 / Windows 托盘上的点击与落位**——本机无 GUI、
      且 Linux 根本不发托盘事件，这一格在这台机器上无法观察。
      面板相对托盘图标的实际位置，要在 mac/win 真机上看过才算数。
