Finding
- User screenshot shows task owner/Agent fields saying loading, not chat loading.
- Source had an unbounded people GET/body read, loading replacing known names,
  and the detail panel did not receive the directory error state.
- Detail owner and participant editors had independent directory/error states.
- A single read-only local Hub probe returned 200 in 77 ms with 286 people.
  That node-authenticated local request does NOT explain the phone network stall.

Change
- 10 s deadline includes fetch and JSON body; abort plus Promise.race also settles
  for an abort-ignoring transport. Failed/completed in-flight entries are evicted.
- Concurrent requests coalesce only for the same server/token/network identity.
- Known names remain visible. Cached choices open without waiting for refresh.
- One directory/error/retry flow serves detail owner and participants.
- A failed participant write is not replayed by the directory retry action.
- Writes, authentication and server authorization are not relaxed.
