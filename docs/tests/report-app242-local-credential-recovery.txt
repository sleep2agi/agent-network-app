app#242 — Local workspace: lost native credential → automatic recovery (2026-09-05)

Trigger
- Vincent (CommHub ea65cfd2 / f8465163, 13:42): Settings → 账号与 Hub → Local workspace shows
  "No matching entry found in secure storage"; 本地 Hub 状态 已停止; asked for automatic
  re-creation + start. Desktop v0.2.46.

Root cause (src-tauri/src/lib.rs, local_hub.rs @ 5a69bec)
- activateProfile → switch_desktop_profile → output_for → keyring get_password(hub-profile-local-workspace)
  → keyring::Error::NoEntry → its Display text is exactly the message on screen. Profile switch never
  starts the local Hub (only cold start does, and only when the saved active profile is local).
- existing_local_session() propagated the same NoEntry with `?`, and bootstrap() with the bootstrap
  password gone said "use diagnostics or explicit local-data reset" — i.e. delete the workspace.

Fix (this PR)
- src/local-hub.ts activateHubProfile: on desktop, LOCAL_HUB_PROFILE_ID → start_local_hub first, then
  switch; App.tsx activateProfile delegates to it (source contract in src/local-hub-activate.test.ts).
- local_hub.rs existing_local_session: NoEntry ⇒ None (not an error). All three start paths
  (already running / external owner / cold start) re-login with the bootstrap password when the
  token is missing and rewrite the profile credential.
- local_hub.rs start_local_hub: bootstrap password missing while the DB exists ⇒ before spawning,
  holding the ownership lock: backup_local_hub_stopped(), then
  local_credentials::reset_local_user_password(db, "local-admin", new random) — writes
  `scrypt$14$<salt>$<hash>` exactly as commhub-server hashPassword, deletes user-level api_tokens
  (same WHERE as revokeOtherUserTokens(user, null)), audit_log row — then stores the new password in
  the keychain and continues with the normal login. No data row other than that user's hash/tokens
  is touched; a missing local-admin user is an error, never an insert.
- New packaged smoke --smoke-local-hub-lost-credential (release gate + main.rs flag): start → stop →
  delete both keychain entries → positive control: switch_desktop_profile must FAIL → start →
  session authenticates (/api/auth/me 200), profile_id unchanged, token rotated, old token 401,
  commhub.db still there, one more backup dir, switch succeeds.
