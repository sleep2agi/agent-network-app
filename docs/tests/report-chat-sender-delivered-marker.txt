## What shipped wrong in 0.2.31

#126 changed who a request bubble is attributed to and left the `已送达 ✓`
marker on every row. The result is a bubble credited to another node with
"delivered" underneath — which reads as "you sent this, and it arrived".

Before either change every row was labelled `我`, so the marker agreed with the
label. Correcting the label alone made this spot **less** coherent than it was
before, not more. That is the shape worth remembering: a partial fix to a
display that had two wrong halves can leave it worse than untouched.

## Provenance

PR #55 (opened 2026-08-22, still open) had already solved this, and two further
cases. It was open when #126 landed and was not found: the duplicate search used
keyword matching with a result limit, and #55 ranked below the limit. A path
overlap check would have caught it — and did, when run before this change:

Its three rules are adopted here with credit.

## Change

`src/chat-sender.ts` — `resolveSender()` returns `{alias, isCurrentUser}`:

- `_localId` present → the viewer's, whatever `from_name` claims. An optimistic
  echo is ours by construction; provenance cannot outrank that.
- viewer's name still the placeholder (`GET /api/auth/me` unresolved) → nothing
  can be classified against an unknown name, so rows stay on the current-user
  side. Judging during that window would push the viewer's own messages to the
  far side for a frame and, now that the marker follows ownership, take
  `已送达 ✓` with them and put it back.
- otherwise `from_name`, with the legacy `api` label mapping back to the viewer
  (rest-identity.ts records it when a user-token request carries no resolvable
  identity, so leaving it raw renders the viewer as a stranger).

`src/ChatScreen.tsx` — author line and avatar use `sender.alias`; the delivery
marker is gated on `sender.isCurrentUser`.
