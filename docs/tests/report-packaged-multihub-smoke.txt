Packaged multi-Hub acceptance gate
Date: 2026-08-24

Scope
- Run three real secured bundled CommHub processes from the exact packaged app:
  local Hub A plus remote profiles B and C.
- Persist all three profiles in the platform credential backend, then verify
  A -> B -> C -> A switching without endpoint/token leakage.
- Launch a fresh copy of the packaged executable while all Hubs are live and
  verify all native sessions, scoped windows, and A-only outbox survive; then
  stop/restart all Hubs and verify all sessions remain valid.
- Revoke only Hub B's live user token, mark only B for reauthentication, and
  prove Hubs A and C remain authenticated.
- Persist the same `worker` detached chat under all profile directories and
  an offline outbox entry under A only.
- Remove B and verify its credential/profile directory disappears while A and
  C are still present and authenticated.
- The separate local-Hub packaged smoke reserves port 9200 before first start
  and requires an automatic loopback fallback, covering real port conflicts.

Required gates
- Docker Bun application suite.
- Docker Rust local_hub suite.
- Exact signed macOS and Windows packaged-executable workflow.
- Credential markers must not appear in smoke logs for A, B, or C.
