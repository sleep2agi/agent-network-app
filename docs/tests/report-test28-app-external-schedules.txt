## 契约/安全事实（App 是 RFC-036 第一个客户端）

1. 读侧走全量 /api/status——Hub server.ts 的 light=1 分支只回 8 字段，
   external_schedules 会被剥掉；断言钉死 URL 不含 light。
2. 同一 node_id 多条会话取 updated_at 最新的快照（与 Hub reportedSchedule
   同准则）；无 node_id 的纯会话、无快照的会话都被跳过（断言含分母）。
3. 写侧 POST /api/nodes/:id/external-schedule-edits 的 body 恰为契约四键
   {network_id, schedule_id, base_revision, patch}——Hub exactKeys 拒绝多余
   键；断言按排序键名逐字比对。
4. 鉴权：App 登录（POST /api/auth/login 用户名/密码）换取登录用户的 Hub
   user token，所有请求 Authorization: Bearer <该 token>；#688 requireOwner
   要求 caller 是 user token 且 user_id === owner_user_id——非 owner 得
   403 node_owner_required，App 逐码映射为中文提示。App 从不持有 ntok。
5. 编辑面仅 enabled + 五段 cron；本地 looksLikeCron 预检（五段、
   [0-9*/,-] 白名单）只挡明显敲错，权威校验在 Hub
   parseManagedCronExpression；UI 文案明示绝不下发命令。
6. 409 逐码映射：revision_conflict / edit_in_flight / schedule_read_only /
   node_owner_required / cross_network_node；冲突后自动刷新快照再操作。
