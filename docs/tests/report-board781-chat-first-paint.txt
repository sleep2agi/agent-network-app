Board #781 (parent #780), app issue #765: independently paint chat sources
Date: 2026-10-08
Base: ee7cda0b82e17ef21c655ab04bd01f2c36e5daab

Scope
Only ChatScreen loading: tasks and proactive messages publish independently.
Successful reads replace their own source and keep the other source and local echoes.
Failed reads are not empty results. Existing pagination/echo reconciliation stays in use.
On a cold load, both successful reads are required before unread acknowledgement readiness.
Existing warm-cache readiness behavior is unchanged.
Stale window/generation/overlapping refresh answers cannot update screen or cache.
No Hub/API/schema/permission/startup/version change. No live node or production operation.

Evidence: Docker only, --cpus=2; exported production ChatScreen + in-page placeholder HTTP.
Browser baseline (pre-fix bundle): rc=1, 3/4 checks passed.
  Task response completed in ~160ms; proactive response held 4000ms.
  Already received task content was still not visible at 1835ms, while the slow read was pending.
  Both sources eventually appeared. This establishes a client-side waiting dependency,
  not proof that it is the user's only real-world bottleneck.

Fixed browser: rc=0, 16/16 checks.
  Desktop 1200x800: first fast message visible in 382ms (slow proactive), 404ms (slow tasks).
  Android-UA/touch 390x844: 274ms (slow proactive), 249ms (slow tasks).
  Every first-paint assertion confirms the slow 4000ms request is still pending.
  Both sources are eventually retained once; partial failures keep visible rows;
  switching conversation with an in-flight read does not show the previous agent's messages.
  Screenshots inspected: docs/tests/board781/{desktop,phone}-loaded.png.
  These are isolated fixture timings, not production measurements or native-device certification.
