## The defect

The agent list scrolls with the platform's default scrollbar. On the dark theme
that is a white gutter down the right edge of a near-black panel.

## Why it could not be fixed where the list is

React Native styles cannot express `::-webkit-scrollbar` — it has no equivalent
in the RN style system — and this repository has no global stylesheet to put it
in. It is an Expo RN-web app with no CSS files at all.

So the rules are generated from the same theme tokens every component reads and
injected once into the document. Per-list styling would mean copying the same
block into every scrollable panel and re-copying it whenever a token moves.

## Change

`src/web-scrollbar-css.ts` — pure: `scrollbarCss(palette)` builds the rules from
`textMuted` (resting thumb) and `textSecondary` (hover/active). Split out of the
DOM half deliberately: react-native's entry point ships Flow syntax
(`import typeof * as …`) that the bun runner cannot parse, so a test importing
anything that pulls react-native in dies before asserting anything.

`src/web-scrollbar.ts` — injects a single `<style id="anet-scrollbar-theme">`,
reuses it on later calls, and re-renders it through `onThemeChange`. No-ops off
web and when there is no `document`.

`App.tsx` — installs it once alongside the existing theme subscription.

Three decisions worth stating:

- **The track stays transparent.** Painting it any colour reintroduces the
  original defect the moment a panel's background differs from the one assumed
  here. Transparent inherits whatever the scrolling element already has and
  cannot mismatch — that, not the thumb colour, is what removes the gutter.
- **Firefox is covered.** It has no `::-webkit` pseudo-elements; without
  `scrollbar-width` and `scrollbar-color` the fix would exist only in Chrome,
  Edge, Safari and the Tauri webview, and Firefox users would still see white.
- **Pointer devices only.** Touch surfaces already overlay a scrollbar that
  hides itself; narrowing it there removes grab area and fixes nothing.

Width is 7px, thumb `border-radius: 999px`, hover/active one token brighter.

## Revision 2: the lifecycle guards were text, not behaviour

Review demonstrated two sabotages that the first revision passed 26/26:

- appending a **fresh** `<style>` on every call — the source still contained
  `getElementById(STYLE_ELEMENT_ID)` somewhere, which is all the assertion
  looked for;
- an installer returning `() => {}` — the source still contained
  `onThemeChange(apply)`.

Both guards described the behaviour instead of exercising it. That is the same
failure this branch already hit one level up, and the correct reading is not
"add two more regexes" but "regexes cannot see lifecycle at all".

`src/web-scrollbar-dom.ts` now holds the DOM work and takes its document and its
theme subscription as arguments, so the test supplies fakes and observes what
lands in `head`. `src/web-scrollbar.ts` is reduced to the platform check and the
wiring to the real palette.

What is now measured rather than described:

- a second apply **reuses** the element (head still holds exactly one) and it
  carries the newest css;
- separate documents get separate elements;
- a missing `head`, and a missing document, are no-ops rather than throws — the
  fake throws from `getElementById`/`createElement` if either is reached;
- after install a theme change rewrites the css; **after teardown it does not**;
- the listener is genuinely removed;
- StrictMode's install → cleanup → install leaves **one** live listener and
  **one** style element, and the surviving installer still tracks the theme.

The active thumb also steps past hover to the `text` token. While dragging, the
thumb is what the pointer is holding; feedback identical to hover leaves a drag
looking like a hover that failed to catch. "Stronger" here is contrast, not
brightness — on the light palette that step is *darker*.

A CSP note now sits at the injection site: this creates a `<style>` element at
runtime, so any `style-src` policy added later must permit it (nonce or
`'unsafe-inline'`). Otherwise the rules are dropped silently and the scrollbar
reverts to the platform default with no error anywhere.
