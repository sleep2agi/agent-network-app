Behavior changed
- A pending outbox row stays pending across process restart. It is unknown until Hub reconciliation, not a proven failure.
- A timeout refreshes the authoritative task list before exposing a red retry action. If the Hub row exists, the optimistic row is retired.
- One optimistic bubble owns one dreq correlation id. Repeated retries reuse it, including deterministic migration for legacy local-* rows.
- Historical failed `local-*` rows from pre-dreq builds are retired and the cleaned outbox is persisted at boot; they cannot be retried idempotently and no longer repopulate every conversation.
- The sidebar window reuses one ChatScreen while aliases change. A send started in A now captures A's conversation key; after switching to B, A's late success/failure may reconcile only A's cache and can never mutate B's visible state or borrow B's request token. The fixed-alias detached window follows the same ownership rule.
