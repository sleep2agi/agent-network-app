## Revision 2: three review blockers

Review of revision 1 (6b8d5c90fe39ea46) found three, all fixed here.

1. **scrub CI was FAILURE and this report did not say so.** The SOP spelled the
   Cargo lock package header literally, twice; scrub-guard reads a doubled
   bracket around a lowercase token as an internal memory slug. The section now
   identifies the entry by its `name` field. Revision 1's evidence was
   incomplete rather than wrong: it ran npm test, typecheck and a YAML parse,
   and never ran the gate that was red. The container now replays scrub too, so
   this class of miss cannot repeat silently.
2. **Section 5 contradicted itself.** It required the tag ref to resolve before
   publishing, while the same work established that GitHub creates the tag at
   publish time — a draft never has one, so the condition could not be met. The
   audit is now split: targetCommitish, job conclusions and assets before
   publishing; the tag ref immediately after, before the manifest sync. A tag
   present *before* publishing is now named as the alarm.
3. **Section 8 said an authorized reuse "re-binds" the tag**, contradicting the
   rule that a tag ref is never moved. Reuse now requires deleting assets by ID,
   removing the failed draft, and confirming no remote tag of that name exists;
   if one does, the version is spent. Section 2 gained the matching preflight,
   since tauri-action resolves a release by tag name and otherwise appends to an
   existing draft.

## Revision 3: size figures corrected

The SOP's size-ceiling paragraph read "48.7 MB — roughly 6 MB of headroom",
which mixed decimal MB against a gate expressed in MiB. `find -size +55M` uses
MiB, so the limit is 55 × 1,048,576 = 57,671,680 bytes. Measured from the
published v0.2.30 assets:

    .msi          48,742,400 bytes  = 46.48 MiB   headroom 8,929,280 B = 8.52 MiB
    .dmg          36,541,885 bytes  = 34.85 MiB
    .app.tar.gz   35,817,590 bytes  = 34.16 MiB
    -setup.exe    35,169,470 bytes  = 33.54 MiB

The error was conservative — it understated the remaining room — so nothing
built on it was unsafe. It is corrected because the paragraph exists to be used
as an arithmetic input, and an input with the wrong base is not usable.

The same query produced the trend now recorded alongside it: the `.msi` moved
between 9.46 and 9.55 MiB from v0.2.9 to v0.2.23, then to 46.43 MiB at v0.2.25
(4.9×), matching the bundling of the pinned local CommHub sidecar and the
supervised local Hub (#95, #96). v0.2.24 has no published release — it is one
of the leftover drafts noted in section 2.
