# Client UI language

Use `useTranslation()` inside rendered components. It subscribes to preference
changes without remounting the component, preserving drafts and navigation state.
`t(key, { name: value })` is also available in event handlers and pure presentation
helpers. Do not translate Agent replies, aliases, user input, file contents or wire
protocol markers.

Register `[Chinese, English]` pairs with `registerTranslations()` in a small
feature table imported by that feature. Keep interpolation names identical in
both languages. Avoid evaluating translated UI labels once at module load: keep
stable keys or compute labels at render time.

Preferences are `system`, `zh`, `en`. System locales beginning with `zh` use
Chinese; other locales use English. Browser/Tauri stores `anet.language.v1` in
localStorage and listens for cross-window updates. Native stores only the
preference in `documentDirectory/language_v1.txt`; unreadable storage falls back
to system, and failed writes still allow session-only switching. No credentials
or Hub state are involved.

Task board, requirement details, subrequirements, project management and dispatch
log now use `i18n-tasks.ts`. Presentation adapters translate generated labels,
not stored identities, dates, titles or descriptions. The numbered task catalogue
is append-only. Extend the explicit file boundary in
`src/i18n-copy-guard.test.ts` when migrating another surface. Chinese UI literals
in guarded files fail; a protocol/data exception requires an adjacent
`// i18n-allow: reason` comment. Comments themselves are not UI copy.

Settings → Appearance exposes Follow system / 中文 / English on both layouts.
Settings labels, search, appearance controls, shortcuts and voice settings use
the same registry. Settings search accepts either language. The numbered settings
catalogue is append-only: do not reorder pairs, because components reference its
stable indices. New feature tables should prefer named keys.

This is a bounded first migration, not a claim that every screen is bilingual.
login/onboarding, nested node-management/image tools and runtime/service error
messages remain outside the boundary. User and Agent content is never translated.
Native storage is covered through the adapter contract; browser screenshots are
responsive-web evidence, not native Android/iOS installation acceptance.
